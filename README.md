# 沪深300 · V4 策略控制台

面向桌面端与移动端的零前端依赖静态仪表盘。核心展示：V4三状态仓位、新资金建仓等级、ETF份额冲击、PE五年分位、价格趋势、策略/满仓回测对比。

## 本地运行

```bash
python -m http.server 4173
# 打开 http://localhost:4173/
```

## 数据更新

网站正式仓位按周确认，但页面每天刷新前一交易日的诊断数据。部署到 GitHub Pages 后，`.github/workflows/update-and-deploy.yml` 每天 **01:00 UTC（北京时间09:00）** 自动运行：

1. 安装 `requirements.txt`；
2. 通过 AKShare 封装的中证指数/上交所/深交所公开数据接口刷新行情与ETF份额；
3. 重新计算104周资金流分位、五年PE分位与趋势；
4. 仅在完整周度观察点更新正式状态；
5. 写入 `public/data/v4-snapshot.json` 并部署 GitHub Pages。

如果任一远端源失败，脚本不会猜测数据，而是保留上一成功快照并把状态标记为 `stale`。

## V4固定规则

- 基准持有：100%。
- 高估值极端赎回 + 价格转弱：进入下行预警，50%。
- 趋势确认恶化、第二次赎回，或大额申购后价格继续破位：风险防御，10%。
- 防御后只有高质量申购启动修复窗口，并由13周趋势转正确认，才恢复100%。
- 新资金采用独立四级建仓判断：强势建仓 / 标准建仓 / 防御试仓 / 等待。
- ETF份额冲击是启动信号，不能解释为确定的“主力买卖”。

## 数据口径

- 沪深300价格与滚动PE：中证指数公开数据。
- ETF份额：上海证券交易所、深圳证券交易所公开数据（通过 AKShare 接口封装）。
- 首次实时运行会建立滚动份额缓存，之后只追加缺失周。
- `public/data/v4-snapshot.json` 初始为 2026-07-31 的研究快照；首次自动任务成功后 `status.mode` 变为 `live`。

## GitHub Pages

1. 将目录推送到 GitHub 仓库的 `main` 分支。
2. Repository Settings → Pages → Source 选择 **GitHub Actions**。
3. 手动运行一次 `Update V4 data and deploy Pages`，用于建立初始份额缓存。
4. 之后每天北京时间09:00自动刷新。

> 策略信号不构成投资建议；份额流入不等同主力买入。
